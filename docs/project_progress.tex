\section*{Abstract}
We built a multi-agent loan-default scoring system for LendingClub Grade C--G
loans. An XGBoost numeric baseline produces a per-borrower default probability;
a panel of LLM agents reads the borrower's free-text description, audits a
proposed text-fusion weight, and merges text-derived risk into the model in
logit space. The system is exposed through a Streamlit single-page demo
backed by a training notebook. The headline result is \emph{not} that text
fusion improves the global model --- on a 4{,}199-row test set the Strategist
AUC is essentially tied with baseline ($+0.001$, $p = 0.11$). The headline
result is that the multi-agent system \emph{learns to distrust text by
default} and lets it act only on a high-confidence subset, where it does
deliver a real \mbox{$+0.0142$ AUPRC} lift. The body of this document
explains the architecture, data pipeline, and the evidence behind that
finding so each team member can present a coherent slice.

\section{System at a glance}
There are two user-facing surfaces and one shared model artefact:

\begin{itemize}
  \item \texttt{app/ui/Home.py} --- single-page Streamlit demo. Loads the
        model pickle directly, calls the LLM endpoint inline. No backend
        service.
  \item \texttt{notebooks/loan\_default.ipynb} --- training notebook. Loads
        the consolidated text-analyst output, retrains XGBoost, runs the
        multi-agent strategy loop, writes \texttt{models/loan\_default\_model.pkl}.
  \item \texttt{evaluation/} --- a 5-module offline toolkit (pipeline
        comparison, per-agent KPI, ablation, trust calibration, report).
        Driven by \texttt{notebooks/eval\_verify\_p3.py}, which writes
        \texttt{docs/eval\_report\_sample1.md} --- the file the UI's
        ``Offline evaluation'' panel renders.
\end{itemize}

Five agents collaborate inside the loop:

\begin{center}\small
\begin{tabular}{@{}p{0.20\linewidth}p{0.20\linewidth}p{0.55\linewidth}@{}}
\toprule
\textbf{Role} & \textbf{Type} & \textbf{Job} \\
\midrule
Text Analyst       & LLM        & Scores the borrower description into a
risk score and self-reported confidence; falls back to a regex scorer when
the LLM cannot be parsed. \\
Feature Strategist & LLM        & Picks one of five \texttt{strategy\_type}s
(\texttt{keep\_learned}, \texttt{case\_specific\_exception}, \texttt{fuzzy\_only},
\texttt{explanation\_only}, \texttt{human\_review}) and proposes a per-grade
text weight. Strict rule: \texttt{case\_specific\_exception} must propose
\emph{strictly greater} than the learned weight. \\
Subgroup Advocate  & LLM        & Reasons about grade-level historical text
impact; emits \texttt{pass / soft\_veto / hard\_veto}. Soft vetoes route to
arbitration; hard vetoes are enforced. \\
Green Agent        & LLM + ML   & Hub: runs the XGBoost baseline, evaluates
fusion, generates expectations and reflects (Reflexion), arbitrates on veto,
and validates with adaptive thresholds. \emph{The Arbitrator is Green ---
there is no separate White Agent.} \\
Reporter           & LLM + det. & Writes a two-paragraph case audit: P1
covers the prediction result, P2 covers whether the text deserved to be
trusted. Includes a Python-only deterministic fallback so the panel
never goes blank. \\
\bottomrule
\end{tabular}
\end{center}

\section{Data pipeline}
Text analysis is done offline by \texttt{text\_analyst.py} (kept out of the
repo because it carries user-specific API credentials). It runs against
three sample csvs of 7{,}000 borrowers each and writes per-sample pickles
to \texttt{text\_ana\_results/}. We consolidate those three runs into
\texttt{text\_ana\_results/text\_analysis\_combined.pkl} (21{,}000 rows,
44\,MB). Every consolidated row carries:

\begin{itemize}
  \item the LendingClub loan \texttt{id} (recovered by joining each sample
        csv row-for-row, since within-file row order is verified to align
        with the pkl's \texttt{idx})
  \item \texttt{\_source\_run}, \texttt{\_source\_idx}, \texttt{\_global\_idx}
        for full provenance
  \item all 30 original text-analyst fields (scores, confidences, raw LLM
        previews, fairness flags, etc.)
\end{itemize}

The training notebook \texttt{cell~12} now uses an \texttt{id}-join
against this consolidated pkl. Replaying the stratified 80/20 split on
\texttt{loan\_default.csv} and inner-joining gives:

\begin{center}\small
\begin{tabular}{@{}lrrr@{}}
\toprule
& \textbf{Train} & \textbf{Test} & \textbf{Default rate} \\
\midrule
Old (sample1, idx-join)     & $\sim$250 & 60   & 0.250 \\
\textbf{New (combined, id-join)} & \textbf{16{,}801} & \textbf{4{,}199} & 0.222 \\
\bottomrule
\end{tabular}
\end{center}

That is roughly a $67\times$ jump in training size and $70\times$ in test
size. All evaluation numbers below come from this new split.

\section{The main finding}

\begin{finding}
\textbf{Text fusion has near-zero benefit on the full test set, but a real
positive lift on the high-confidence subset. The system has learned to
distrust text by default and gate it through.}

\smallskip
\textbf{Evidence (combined.pkl test, $n = 4{,}199$):}
\begin{itemize}
  \item Per-grade $\Delta\mathrm{AUC}$ at the learned weight is essentially
        zero for every grade: C $-0.0005$, D $-0.0027$, E $+0.0001$,
        F $-0.0008$, G $-0.0030$. Strategist vs baseline overall is
        $\Delta\mathrm{AUC} = +0.0011$, DeLong $p = 0.11$.
  \item Restrict to the top 35\% of rows ranked by text confidence and the
        gap reverses: fused AUPRC beats baseline AUPRC by
        \textbf{$+0.0142$}. Confidence-vs-accuracy slope is $+1.40$ (high
        claimed confidence really is more reliable).
  \item The learned \texttt{best\_strategy} reflects exactly that:
        \emph{small weights everywhere, strict gate}.
\end{itemize}
\end{finding}

The learned policy, side by side with the previous (small-sample) model:

\begin{center}\small
\begin{tabular}{@{}lccccccc@{}}
\toprule
& \textbf{C} & \textbf{D} & \textbf{E} & \textbf{F} & \textbf{G} & \texttt{conf\_threshold} \\
\midrule
Old (sample1, $n \approx 250$)            & 0.03 & \textbf{0.13} & 0.08 & 0.06 & 0.03 & 0.67 \\
\textbf{New (combined, $n = 16{,}801$)}   & 0.03 & \textbf{0.10} & 0.05 & 0.03 & 0.03 & \textbf{0.65} \\
\bottomrule
\end{tabular}
\end{center}

In sample1, the D weight of $0.13$ looked like genuine text benefit. At
$67\times$ the data, that benefit shrinks to a $0.10$ weight whose own
\texttt{grade\_train\_stats} entry is mildly negative ($-0.003$). The same
relaxation happens on E and F. The takeaway for a presentation slide:

\begin{quote}\small\itshape
``The small-sample model was over-confident about how useful text is. At
real scale the multi-agent system converges to a much more conservative
policy: it touches text only on the cases where the borrower description
is concrete enough to earn its place, and it pays for itself there.''
\end{quote}

\begin{center}\small
\begin{tabular}{@{}lrrl@{}}
\toprule
\textbf{Method} & \textbf{Test AUC} & \textbf{$\Delta$ vs baseline} & \textbf{Note} \\

Two readings of the same table:
\begin{itemize}
  \item Pessimist: MAS only beats brute-force grid search by $+0.0008$ AUC.
  \item Honest: with this baseline strength and this much data, the
        Strategist matches an exhaustive brute-force search while making
        five small \emph{interpretable} decisions per grade. The win is
        \emph{auditability + selective use of text}, not raw AUC.
\end{itemize}

\textbf{Trust calibration (the headline section).} The offline report's
\texttt{trust\_calibration} verdict on combined.pkl reads:
\begin{quote}\itshape
``confidence is a real trust signal; selective fusion helps''
\end{quote}
This is the affirmative branch of a four-way verdict tree. The previous
sample1 report instead read ``\textit{confidence tracks accuracy but fusion
gains are flat at the top}'' --- the noisy small-sample reading. The
$67\times$ data jump turned an inconclusive picture into the one the
system was designed for.

\section{Implementation notes worth defending}

Three engineering conventions are load-bearing and should be preserved
when extending the system. They are documented in the README and recapped
here so a team member can answer a ``why is it like this'' question:

\begin{enumerate}
  \item \textbf{All LLM calls use JSON output mode.}
        MiniMax-M2.7 is a thinking model. In free-text mode it leaks
        \texttt{<think>...</think>} blocks or stream-of-consciousness
        reasoning that exhausts the token budget \emph{before} producing
        the actual answer --- the user-visible output ends up blank or
        truncated. JSON mode reliably suppresses this. Every agent
        (Text Analyst, Strategist, Advocate, Green LLM, Arbitrator,
        Reporter) emits a JSON object that the UI parses locally with
        \texttt{\_extract\_json\_object}.
  \item \textbf{The Reporter has a deterministic Python fallback.}
        \texttt{\_reporter\_deterministic\_fallback} synthesises the
        two-paragraph narrative from numeric inputs alone, matching the
        prompt's structure (P1: prediction result, P2: trust assessment;
        with separate branches for \texttt{effective\_weight = 0} vs
        $>0$). The Reporter panel can never go blank, even when the LLM
        returns invalid or truncated JSON.
  \item \textbf{The \texttt{reasoning} field carries borrower-level
        analysis, never system status.}
        \texttt{fallback\_text\_analyst} writes \texttt{reasoning} as a
        sentence about the borrower's text; system-level failure detail
        (e.g. ``LLM JSON parsing failed: \ldots'') goes into a separate
        \texttt{\_fallback\_reason} field that never flows into another
        agent's prompt. This is what stops the Reporter from confusing
        system state for borrower narrative quality.
\end{enumerate}

\section{Repository status and how to run}

\textbf{Current branch:} \texttt{main} on
\url{https://github.com/junwei-li057/loan-mas-project}. Most recent
commit at the time of writing is the consolidated retrain
(\texttt{058855f}). The pipeline is self-consistent: model trained on
combined.pkl, offline report regenerated on the same split.

\textbf{To run the demo (no LLM credits required):}
\begin{verbatim}
pip install -r requirements.txt
streamlit run app/loan_demo.py
\end{verbatim}
The XGBoost baseline, four preset borrowers, and ``Offline evaluation''
panel work without an API key. Setting \texttt{MINIMAX\_API\_KEY}
activates the LLM agent panels.

\textbf{To regenerate the report after retraining:}
\begin{verbatim}
python notebooks/eval_verify_p3.py
\end{verbatim}

\textbf{Suggested presentation flow (15--20 min):}
\begin{enumerate}
  \item Motivation: numeric features alone leave free-text on the table;
        but naive text fusion is risky.
  \item Architecture: walk through the 5 agents using the table in
        Section 1; emphasise that Green plays both ML hub and arbitrator.
  \item Live demo of \textbf{Case 1 (Grade C, hard veto)} or
        \textbf{Case 2 (Grade E, arbitration)} --- shows the full
        Strategist $\rightarrow$ Advocate $\rightarrow$ Green flow on a
        single borrower.
  \item The main finding (Section 3), framed as
        ``\textit{the system learned to distrust text by default}''. Show
        the weight table to make the small-sample-overconfidence story
        concrete.
  \item Ablation table (Section 4) as a credibility anchor: MAS matches
        an exhaustive brute-force grid search with five interpretable
        scalars.
  \item Close on the trust calibration verdict: the design assumption
        was vindicated only at scale.
\end{enumerate}
